# 自动化

## 新建规则

1. 先保存要执行的快捷指令。
2. 打开底栏“自动化”，新增规则，填写名称。
3. 选择触发条件并填写所需参数，选择目标快捷指令后保存。
4. 确认规则启用，通知权限及后台运行条件可用，前台监视通知存在。

规则可编辑、启用 / 停用、删除。监视服务的常驻通知提供暂停入口；暂停后应按应用提示恢复，避免误以为仍在监视。

## 支持的条件

| 条件 | 参数与行为 |
| --- | --- |
| 指定时间 | 使用 M3E“选择时间”设置，本地 `HH:mm`，按分钟匹配，每天同一规则去重 |
| 电量低于 | 1–100 阈值，电量严格小于时满足 |
| 接入 / 断开电源 | 按充电状态变化判断 |
| Wi-Fi 连接 | Wi-Fi 连接状态满足 |
| 指定 Wi-Fi | 指定 SSID，当前连接名称相同才满足 |
| 网络连接 | 系统报告网络连接 |
| 屏幕开启 / 关闭 | 系统屏幕事件 |
| 开机 | 接收到开机事件后尝试执行 |
| NFC | 预先扫描卡片 ID，接收到相同卡片事件时执行 |

状态条件通常在从“不满足”变成“满足”时触发一次，不会每次检查都重复运行。启动监视时已满足的状态条件可以触发一次；NFC 和屏幕等事件条件依据对应事件。

“选择时间”提供 M3E 表盘与键盘模式，遵循系统 12 / 24 小时偏好并按当前语言显示；取消不修改原时间，确认后仍保存兼容原有规则的 `HH:mm`。

可在设置 → 权限打开系统无障碍页面，手动启用“Shortcuts 自动化辅助”。服务连接时会尝试恢复已经启用且未被暂停的监视流程，不读取屏幕、不执行手势；这是可选辅助，不能保证后台常驻，电池优化及厂商后台策略仍适用。

## 指定 Wi-Fi

应用会尝试读取系统可见的已保存 Wi-Fi 名称并提供选择。Android 版本、定位开关、精确 / 后台位置及附近 Wi-Fi 权限、厂商策略会限制 SSID 和配置列表；返回空列表不代表设备没有保存网络。

按界面填写 / 选择正确 SSID，并在设置确认相关权限。规则识别的是当前连接网络，不会替你主动连接 Wi-Fi。

## NFC

配置时先扫描目标卡片并保存 ID。不支持 NFC 的设备，该条件会禁用；支持的设备也需要启用系统 NFC。

运行依赖 Android 把卡片事件派发给本应用，并非后台持续原始读卡。锁屏、系统 NFC 行为、卡片类型和其他应用的处理优先级都可能影响触发，不能保证锁屏或所有卡片都能运行。

## 后台交互

后台流程遇到要求输入、菜单、快速查看、系统授权或打开应用等交互时，会通过通知提示返回软件，在同一次运行中继续等待。不会为了继续而重新执行前面已完成的文件写入、通知、安装等步骤。

如果通知不可用，交互会明确失败。进程被系统结束后，不会自动恢复正在进行的流程。

## 调度边界

- 时间规则由监视服务约每 15 秒检查一次，没有精确闹钟、唤醒锁或漏跑补偿；休眠可能推迟或错过对应分钟。
- 多条自动化按队列处理，最多等待 16 个触发；不是无限并行执行。
- 最多保存 100 条规则，每条 XML 最多 64 KiB。
- 系统强制停止、厂商后台限制或权限变化可能阻止监视和开机恢复。
- 忽略电池优化与允许自启动可改善后台运行，但不保证服务永远存活。

排查时先确认手动运行目标成功，再检查规则状态、常驻通知、后台权限和实际触发条件。
