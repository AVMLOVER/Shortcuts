# 权限与执行模式

## 选择执行模式

设置的执行模式提供标准、Shizuku、Root。普通文本、计算、列表、字典、图像等操作无需特权；涉及系统能力的操作会在执行时检查真实授权。

| 模式 | Shell / APK 安装 | 需要准备 |
| --- | --- | --- |
| 标准 | 应用自身身份运行命令；安装打开系统安装器 | 相应 Android 权限、允许安装未知应用等 |
| Shizuku | 使用已授权 Shizuku 服务的实际身份；安装请求通过 `pm install` | 已启动 Shizuku，并授予 Shortcuts 访问权限 |
| Root | `su` 授权后的命令及 `pm install`，支持特权文件目录 | Root 环境及管理器授权 |

模式选择不是授权。Shizuku 的实际身份可能是 shell 或 root，设备策略仍可拒绝安装 / 命令；本应用自定义系统目录文件操作目前要求 Root，不会因选择 Shizuku 就获得全部目录读写能力。

Root 与 Shizuku 的成功授权分别保存在本机，可同时保留；切换到标准模式、切换特权模式或重启应用不会清空记录。设置保留“授权 / 验证”按钮，便于重新检查。Shizuku 暂时断开时保留“已授权”并显示服务未连接；服务恢复后自动检查实际权限，确认被撤销时清除对应记录，另一模式不受影响。Root 的记录来自上一次成功验证，主动验证失败时更新记录；运行操作仍由 `su` 或 Shizuku 的实际权限决定。记录不写入快捷指令 XML，也不会授予新的系统权限。

## 权限用途

| 权限或设置 | 作用 |
| --- | --- |
| 通知 | 发送通知 / 提醒、监视服务、后台交互返回入口 |
| 无障碍 | 跳到系统无障碍页面，手动启用可选的“Shortcuts 自动化辅助”，辅助后台自动化 |
| 忽略电池优化 | 降低自动化被省电策略限制的机会 |
| 自启动 / 后台 | 跳到系统应用详情，由用户按厂商界面允许后台运行 |
| 在其他应用上层显示 | 桌面小组件运行后显示顶部结果浮层 |
| 应用列表 | 构建应用选择器和获取应用列表；采用包可见性声明，不一定有标准运行时弹窗 |
| 读取日程 | 读取指定日期事件、查询可用日历 |
| 写入日程 | 创建日程和相关提醒 |
| 相机 | 调用系统拍照窗口 |
| 相册 / 图像 | 读取授权媒体，权限粒度随 Android 版本变化 |
| 位置 | 获取当前位置，及部分 Wi-Fi 名称访问 |
| 后台位置 / 附近 Wi-Fi | 指定 Wi-Fi 自动化所需能力，受系统版本限制 |
| 截图授权 | 每次由系统 MediaProjection 窗口确认 |
| 安装未知应用 | 标准模式使用系统安装器安装 APK |

系统文件选择器授予的是所选文件 / 目录访问权，不等于所有文件访问。媒体权限也不等于允许任意系统目录读写。

无障碍服务与设置页使用相同用途说明：自动化流程可能需要辅助以帮助应用保持后台可用，但系统仍可能结束进程。该服务不请求屏幕内容读取或手势能力，也不监听或保存屏幕事件；不会绕过系统省电限制或强行恢复用户已暂停的监视。

## Shell 的工作目录与确认

Shell 默认在软件自己的工作目录执行，运行前先查看 `pwd` / `ls`。标准 / Root 读取动态管道输出，Shizuku 使用轮询提供动态结果。

对可能写入、删除、复杂组合或无法确定为只读的命令，应用会先要求确认；删除相关提示区分删除行为。已识别的根目录批量删除（如 `rm -rf /*`）及裸设备写入直接拒绝，各模式相同。

这些检查针对常见危险模式，不是完整 Shell 沙箱。确认前应理解命令和实际目录，命令使用的权限取决于当前后端。

## 应用列表与打开应用

“打开应用”提供名称、图标和系统应用过滤，默认隐藏系统应用。Intent 可选择本机应用辅助填写目标包名 / 组件，再按需编辑 action、data、MIME、category 和 extra。

“获取应用列表”输出文本列表，可选包名、应用名称或两者，默认不含系统应用。每批 1–256 项，起始位置从 **0** 开始；获取后续批次可使用 256、512 等偏移。结果以当前系统允许查询的应用为准。

## 授权失败时

检查权限开关、服务是否仍在运行、Root / Shizuku 是否重新授权，以及系统是否禁用了通知渠道。设置入口会跳到系统页面；系统 / 厂商未提供相应能力时，应用不能自行授予权限。
